# Etapa 6. Arquitetura, dados e qualidade

**Objetivo:** Decidir como o produto será construído e o que conta como bom, antes de escrever código.

| | |
|---|---|
| Entra | `requisitos.md`, `escopo.md`, telas aprovadas. |
| Sai | `arquitetura.md` (processo, fluxo, dados, integrações, hospedagem), `qualidade.md` (critérios verificáveis) e as decisões em `esteira/decisoes/arquitetura/`. |
| Quem decide | O dono escolhe hospedagem, servidor e banco. O agente propõe com opções e custo. |
| Roteiro do agente | [prompt.md](prompt.md) |

**Critério de aceite:** cada escolha tem requisito de origem e cada requisito não funcional tem um critério medível.

Regras que valem em toda etapa: [esteira/README.md](../README.md) e [principios-de-perguntas.md](../principios-de-perguntas.md). Decisão tomada aqui vira arquivo em [esteira/decisoes](../decisoes/README.md).
